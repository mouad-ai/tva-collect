Section 1 — Vue d'ensemble

Qu'est-ce que TVA Collect ?

TVA Collect est une application SaaS destinée aux cabinets comptables marocains. Elle centralise les clients, les collectes mensuelles ou trimestrielles, les documents attendus, les dépôts clients, les relances, les contrôles TVA, les preuves opérationnelles et le suivi manuel de déclaration/paiement.

L'objectif n'est pas de remplacer SIMPL-TVA ni la DGI, mais de préparer le dossier, réduire le chaos WhatsApp, suivre les pièces manquantes et garder une preuve exploitable de ce qui a été demandé, reçu, vérifié et relancé.

Workflow principal en langage simple

  1. Le cabinet se connecte puis crée ou importe ses clients.
  2. Le cabinet crée une collecte, par exemple TVA Juin 2026, et choisit les clients concernés.
  3. TVA Collect génère un lien de dépôt unique par client et une liste de documents attendus.
  4. L'assistant copie le lien ou une relance WhatsApp/email manuelle, puis l'envoie au client.
  5. Le client ouvre /upload/[token], vérifie la période, accepte les règles, choisit le type de document et dépose les fichiers.
  6. Le cabinet voit les documents reçus, les classe, les marque valides ou invalides, et suit les pièces manquantes.
  7. Quand le dossier est prêt, le cabinet saisit les montants TVA, vérifie le readiness, puis crée un dossier de filing.
  8. Le cabinet suit manuellement la déclaration, le paiement, les références externes, et exporte les données CSV pour préparer les démarches DGI/SIMPL.

Section 3 — Documentation des fonctionnalités

Le code ne contient pas de marqueurs explicites “Pack 0, Pack 1...” dans les dossiers. Les fonctionnalités sont donc regroupées par domaines fonctionnels, avec indication des migrations ou fichiers techniques principaux.

Domaine — Site public & acquisition

Ce que ça fait : Les pages publiques présentent TVA Collect, la tarification, le contact et la demande de démo. Les leads sont enregistrés dans le CRM interne.

Qui l'utilise : Prospect cabinet, ADMIN SaaS.

Comment l'utiliser

  1. Aller sur /, /pricing, /contact ou /demo.
  2. Remplir le formulaire de contact ou de démo.
  3. Le lead est enregistré et devient visible dans /admin/leads.

Note technique : Pages app/page.tsx, app/pricing/page.tsx, app/contact/page.tsx, app/demo/page.tsx ; API app/api/contact/route.ts ; modèle Lead.

Domaine — Authentification & sécurité

Ce que ça fait : Authentification par email/mot de passe, mots de passe hashés, cookie de session signé, expiration globale et timeout d'inactivité. Les connexions et uploads publics sont limités par des buckets persistants en base.

Qui l'utilise : ADMIN, OWNER, MANAGER, ASSISTANT, READ_ONLY.

Comment l'utiliser

  1. Aller sur /login.
  2. Saisir email et mot de passe.
  3. En cas d'échec répété, le système ralentit les tentatives et affiche un message générique.
  4. Cliquer sur Déconnexion pour supprimer le cookie de session.

Validations : Secret obligatoire en production ; utilisateurs inactifs bloqués ; cookie httpOnly, sameSite lax et secure en production.

Note technique : lib/auth.ts, lib/rate-limit.ts, app/api/auth/login/route.ts, proxy.ts, modèles User, RateLimitBucket.

Domaine — Provisioning cabinets & invitations

Ce que ça fait : TVA Collect dispose d'un vrai flux SaaS multi-cabinets. Un ADMIN plateforme crée un cabinet et son premier OWNER ; le OWNER configure son mot de passe depuis une invitation, puis invite son équipe. Les clients restent des fiches Client, jamais des comptes User.

Qui l'utilise : ADMIN pour créer et gérer les cabinets ; OWNER/MANAGER pour inviter l'équipe ; utilisateurs invités pour accepter leur lien.

Comment l'utiliser côté ADMIN

  1. Créer le premier ADMIN avec npm run create-admin si aucun compte plateforme n'existe.
  2. Se connecter puis ouvrir /admin/firms/new.
  3. Renseigner nom cabinet, ville, téléphone, email, plan, statut, dates de trial, nom owner et email owner.
  4. Valider : le système crée Firm, crée un User OWNER avec passwordHash = null, crée un UserInvite, journalise l'action et affiche/log le lien d'invitation.
  5. Depuis /admin/firms/[id], l'ADMIN peut changer plan/statut, suspendre/réactiver, transférer owner et générer un nouveau lien password.

Comment l'utiliser côté OWNER/MANAGER

  1. Ouvrir /app/settings/team.
  2. Inviter un utilisateur avec nom, email et rôle MANAGER, ASSISTANT ou READ_ONLY.
  3. Envoyer le lien affiché à l'utilisateur invité.
  4. Le OWNER peut aussi transférer la propriété à un utilisateur actif du cabinet.

Comment accepter une invitation

  1. Ouvrir /invite/[token].
  2. Saisir un mot de passe fort et le confirmer.
  3. Le système refuse les tokens expirés, acceptés ou révoqués, hash le mot de passe et marque l'invitation acceptée.

Cycle de vie cabinet : FirmStatus contient TRIAL, ACTIVE, OVERDUE, SUSPENDED, CANCELLED. Si un cabinet est SUSPENDED ou CANCELLED, /app est bloqué sauf /app/billing et /app/suspended, et les uploads publics sont refusés.

Note technique : scripts/create-admin.ts, app/admin/firms/new/page.tsx, app/admin/invites/page.tsx, app/admin/users/page.tsx, app/invite/[token]/page.tsx, app/app/settings/team/page.tsx, lib/invites.ts, lib/email.ts, modèles Firm, User, UserInvite.

Ce que ça fait : La zone admin donne une vue propriétaire sur les cabinets, utilisateurs, invitations, clients, documents, stockage, leads et événements.

Domaine — Tableau de bord & activation

Ce que ça fait : Le tableau de bord montre les KPI, l'activation du cabinet, les actions du jour, les alertes critiques, les uploads récents et les recommandations d'adoption.

Qui l'utilise : OWNER, MANAGER, ASSISTANT, READ_ONLY.

Comment l'utiliser

  1. Aller à /app.
  2. Suivre la checklist : profil cabinet, logo, clients, collecte, lien, premier document, premier rapport.
  3. Cliquer sur les CTA pour ouvrir clients, collectes, documents ou rapports.
  4. Lire les alertes critiques pour prioriser la journée.

Note technique : app/app/page.tsx, lib/adoption.ts, modèles Client, CollectionPeriod, UploadedDocument, ReminderLog.

Domaine — Clients & profil fiscal

Ce que ça fait : Le cabinet crée, recherche, importe et consulte ses clients. Chaque fiche client affiche le profil, l'historique des collectes, le score comportemental et un profil fiscal TVA.

Qui l'utilise : OWNER, MANAGER, ASSISTANT, READ_ONLY.

Comment l'utiliser

  1. Menu Clients ou /app/clients.
  2. Créer un client avec société, contact, téléphone, email, ICE, IF, ville et notes.
  3. Importer des clients par CSV depuis le bloc d'import.
  4. Cliquer sur un client pour modifier ses informations, voir son comportement et ouvrir son profil fiscal.
  5. Depuis le profil fiscal, renseigner ICE, IF, RC, CNSS, fréquence TVA, régime, niveau de risque et responsable dossier.

Contraintes : Les clients supprimés passent en corbeille ; les données sont filtrées par firmId.

Note technique : app/app/clients/*, app/api/clients/*, components/ClientImportForm.tsx, modèles Client, ClientFiscalProfile.

Domaine — Collectes & workflow documentaire

Ce que ça fait : Les collectes organisent les demandes documentaires par période, workflow et client. Elles créent des dossiers clients avec un token public et une checklist de documents requis.

Qui l'utilise : OWNER, MANAGER, ASSISTANT.

Comment l'utiliser

  1. Menu Collectes TVA ou /app/collections.
  2. Créer une collecte : nom, type de workflow, mois, année, clients à inclure.
  3. Ouvrir la collecte pour voir les clients, liens, documents manquants, statut, risque et notes internes.
  4. Copier un lien de dépôt ou ouvrir le portail client.
  5. Ajouter d'autres clients à la collecte si nécessaire.
  6. Changer le statut : brouillon, active ou clôturée.

Workflows disponibles : TVA mensuelle, TVA trimestrielle, CNSS mensuelle, paie, clôture annuelle, documents bancaires, juridiques, onboarding client, documents employés, fournisseurs, custom.

Note technique : app/app/collections/*, app/api/collections/*, lib/constants.ts, modèles CollectionPeriod, ClientCollection, RequiredDocument.

Domaine — Portail client de dépôt

Ce que ça fait : Le client dépose ses documents via un lien public tokenisé. Le portail affiche le cabinet, le client, la période, les obligations, les règles de confiance et l'historique des fichiers reçus.

Qui l'utilise : Client externe ; cabinet pour vérification.

Comment l'utiliser côté client

  1. Ouvrir le lien envoyé par le cabinet : /upload/[token].
  2. Lire la demande, la période et les documents attendus.
  3. Choisir le type de document, ajouter les fichiers, saisir un nom/commentaire facultatif.
  4. Cocher les confirmations obligatoires : retard, période, documents disponibles.
  5. Cliquer sur Déposer les documents.

Sécurité : Le lien est refusé s'il est expiré, désactivé, verrouillé, supprimé ou si la collecte n'est pas active. Les uploads sont limités par IP et token, validés par extension/MIME/taille et reçoivent un scan local CLEAN avec provider NONE.

Note technique : app/upload/[token]/page.tsx, components/UploadForm.tsx, app/api/public/upload/[token]/route.ts, lib/storage.ts, lib/file-security.ts.

Domaine — Documents & validation

Ce que ça fait : Les fichiers reçus sont listés, filtrés, classés par document requis et contrôlés par qualité : à vérifier, valide, mauvais document, illisible, doublon, page manquante ou hors TVA.

Qui l'utilise : OWNER, MANAGER, ASSISTANT, READ_ONLY pour consultation.

Comment l'utiliser

  1. Menu Documents.
  2. Filtrer par client ou collecte.
  3. Choisir une classification dans la liste des documents attendus.
  4. Choisir le statut de contrôle et ajouter un commentaire interne.
  5. Télécharger un fichier si son scan sécurité autorise le téléchargement.

Note technique : app/app/documents/page.tsx, app/api/documents/*, modèle UploadedDocument, DocumentSecurityScan.

Domaine — Relances

Ce que ça fait : TVA Collect génère des messages WhatsApp ou email à copier, avec les documents manquants et le lien de dépôt. L'application garde un historique des relances générées.

Qui l'utilise : OWNER, MANAGER, ASSISTANT.

Comment l'utiliser

  1. Menu Relances ou bouton Relance dans une collecte.
  2. Choisir WhatsApp ou email.
  3. Copier le message généré et l'envoyer manuellement au client.
  4. Consulter l'historique dans /app/reminders.

Important : L'application ne se connecte pas à l'API WhatsApp et n'envoie pas d'email réel ; elle prépare le message et journalise la génération.

Note technique : components/ReminderButton.tsx, app/api/client-collections/[id]/reminders/route.ts, lib/tva.ts, modèle ReminderLog.

Qui l'utilise : OWNER, MANAGER, ASSISTANT.

Comment l'utiliser

  2. Lire le plan “Operations Brain”.

Domaine — Proof Vault & audit trail

Ce que ça fait : Le Proof Vault expose la timeline d'événements opérationnels : création client, création collecte, lien ouvert, règles acceptées, document déposé, document revu, relance, verrouillage, restauration, etc.

Qui l'utilise : OWNER, MANAGER, ASSISTANT, READ_ONLY.

Comment l'utiliser

  1. Menu Preuves.
  2. Filtrer par client ou type d'événement.
  3. Lire la chronologie avec date, source, acteur et description.
  4. Ouvrir la collecte liée si disponible.

Note technique : app/app/proof-vault/page.tsx, lib/operational-events.ts, modèle OperationalEvent.

Domaine — Préparation TVA

Ce que ça fait : Cette zone calcule un score de readiness TVA avant déclaration : documents manquants, documents non revus, documents rejetés, saisies TVA manquantes ou suspectes, TVA nette estimée.

Qui l'utilise : OWNER, MANAGER, ASSISTANT.

Comment l'utiliser

  1. Menu Préparation TVA.
  2. Ouvrir un dossier client.
  3. Saisir les entrées TVA manuelles : achat, vente, frais ou avoir.
  4. Lier une entrée à un document reçu si utile.
  5. Changer le statut de préparation : collecting, review, ready to declare, declared, archived, blocked.
  6. Verrouiller le dépôt client quand la préparation démarre ; rouvrir avec une raison si nécessaire.
  7. Exporter les entrées TVA CSV.

Note technique : app/app/tva-readiness/*, lib/tva-readiness.ts, modèles TvaReadinessCheck, TvaAmountEntry.

Domaine — Déclaration, paiement & preuves fiscales

Ce que ça fait : Le filing suit manuellement l'après-préparation : dossier de déclaration TVA, statut externe, référence, paiement dû/payé, méthode, échéances et reçus fiscaux.

Qui l'utilise : OWNER, MANAGER, ASSISTANT.

Comment l'utiliser

  1. Menu Déclaration TVA.
  2. Créer un dossier filing depuis une période client.
  3. Ouvrir le dossier et vérifier les blocages : manquants, non revus, rejetés.
  4. Verrouiller la période si la déclaration est en préparation.
  5. Saisir le statut de soumission externe, référence et notes.
  6. Saisir le paiement : statut, montant dû, montant payé, date, méthode et référence.

Note technique : app/app/tva-filing/*, lib/tva-filing.ts, modèles TvaFilingCase, TvaSubmission, TvaPayment, FiscalReceipt.

Section 6 — FAQ

1. Comment ajouter un nouveau client ?

Allez dans Clients, remplissez le formulaire “Nouveau client”, puis cliquez sur Nouveau client.

2. Puis-je importer plusieurs clients ?

Oui, via le bloc d'import CSV dans Clients. Le code prend en charge création/mise à jour et erreurs simples.

3. Comment envoyer une demande de documents ?

Créez une collecte, ajoutez les clients, copiez le lien de dépôt ou générez une relance, puis envoyez le message manuellement.

4. Mon client n'a pas reçu l'email de demande, que faire ?

TVA Collect ne fait pas d'envoi email réel. Copiez le message email/WhatsApp généré et envoyez-le depuis votre outil habituel.

5. Le client a déposé un mauvais document, que faire ?

Dans Documents, changez le statut de contrôle en Mauvais document, Illisible, Doublon, Page manquante ou Hors TVA, puis relancez le client.

6. Puis-je empêcher un client d'ajouter de nouveaux fichiers ?

Oui. Dans Préparation TVA ou Filing, verrouillez le dossier client. Le portail public refusera les nouveaux dépôts.

7. Les liens de dépôt expirent-ils ?

Oui, les tokens possèdent une date d'expiration configurée par UPLOAD_TOKEN_TTL_DAYS. Ils peuvent aussi être désactivés.

8. Comment exporter les documents pour la DGI ?

L'application exporte des CSV de suivi et d'entrées TVA. Elle ne produit pas encore de ZIP complet DGI ni de dépôt direct SIMPL.

9. Puis-je modifier une déclaration déjà soumise ?

Le module Filing permet de modifier le statut, la référence et les notes de soumission. Il s'agit d'un suivi interne, pas d'une modification automatique sur SIMPL.

10. Comment savoir si un dossier est prêt ?

Ouvrez Préparation TVA. Le score readiness affiche les blocages, alertes, montants TVA et statut de préparation.

11. Comment récupérer un client ou document supprimé ?

Les rôles OWNER ou MANAGER ouvrent Corbeille, puis cliquent Restaurer.

12. Où voir l'historique des actions ?

Dans Proof Vault, filtrez par client ou type d'événement.

13. Les fichiers sont-ils analysés contre les virus ?

Le modèle de scan existe. En local, provider NONE marque les fichiers propres après validation type/taille. Un scanner réel reste à brancher en production.

14. Qui peut accéder à la facturation ?

OWNER et MANAGER. ASSISTANT, READ_ONLY et ADMIN plateforme ne voient pas le menu Facturation cabinet.

15. Comment créer un nouveau cabinet payant ?

Un ADMIN plateforme ouvre /admin/firms/new, crée le cabinet et son OWNER. Le système génère ensuite un lien /invite/[token] pour que le OWNER configure son mot de passe.

16. Un assistant peut-il inviter d'autres utilisateurs ?

Non. Seuls OWNER et MANAGER peuvent inviter MANAGER, ASSISTANT ou READ_ONLY depuis /app/settings/team.

17. Que se passe-t-il si un cabinet est suspendu ?

Les pages opérationnelles /app sont bloquées sauf /app/billing et /app/suspended. Les liens publics de dépôt refusent aussi les uploads.

18. TVA Collect remplace-t-il le cabinet comptable ?

Non. C'est un outil d'organisation, de preuve et de préparation. Les décisions fiscales et déclarations officielles restent sous responsabilité du cabinet.

Zones ambiguës ou non documentées

  • Le provisioning SaaS existe : ADMIN crée cabinet + OWNER, OWNER/MANAGER invitent l'équipe, et les clients restent sans compte. L'envoi email réel reste abstrait : en développement les liens sont loggés, en production un provider doit être configuré.
  • La facturation est affichée manuellement ; il n'existe pas de paiement en ligne ni de vraie gestion d'abonnement persistante complète.
  • Les exports ZIP, PDF avancés, OCR, IA, DGI/SIMPL API et WhatsApp API ne sont pas implémentés.
  • Les jobs de nettoyage orphelins existent comme stub/dry-run ; pas de cron automatique identifié.
  • La documentation de “packs” n'est pas représentée dans le code par des dossiers ou commentaires. Le regroupement ci-dessus suit donc les domaines fonctionnels et les migrations.
  • Le build Next/Turbopack signale encore un avertissement non bloquant sur le traçage de lib/storage.ts.
